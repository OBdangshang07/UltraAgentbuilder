# Coupled assembly server placement gateway

The grouped coupled protocol has its own server placement service. This is
not an adapter to the older single-patch or whole-assembly writer. The service
does not generate a model response, approve a preview, or expose recovery from
an archived report.

Preparation retains the original server Capture, complete coupled input and
whole preview. Server audit and the full fresh BEFORE scan run before the
read-only CPU plan. Archive reconstruction verifies bytes without replacing
the original audited Compiled object. CPU cancellation makes its result
ineligible immediately; a retiring worker remains excluded until it closes.

Only a separate explicit final confirmation may hand off the original native
lease. Its private owner-bound APPLY ticket is consumed by that lease exactly
once. Confirmation includes acknowledgement that physics and circulation have
not been verified. This short final-confirmation lifetime is not a generation
deadline, provider timeout or output-token limit.

After confirmation, the original grouped journal is created asynchronously in
the world's `voxel-studio-coupled-assembly-journals` directory. The disk must
have at least 2 GiB usable space before creation. The server tick waits for
the original journal result before constructing the execution core. It never
blocks on disk or CPU completion. Per-step limits are 64 member writes and a
2 ms scheduling budget; a one/two-cell operation group has no cancellation or
tick boundary between its members.

All other operation families exclude a coupled preparation or live write.
Outstanding disk work remains busy even if its reply times out. An unknown
write or journal outcome becomes REVIEW_REQUIRED, not permission to retry,
replay, create a replacement journal or overwrite a later player edit.
Stopping a server cancels unconfirmed preparation and closes confirmed work
as review-required if its original outcome is not sealed.

Closing a progress screen must not cancel a confirmed operation. Queries are
limited to the current single-player creative host and matching dimension.
A completed journal does not claim physical region-file persistence.

This server gateway is not a player-facing release: coupled final-confirmation
UI, native protected undo, installed same-asset game tests, physical-save and
client compatibility acceptance are separate gates. Source contracts are
wiring evidence; compilation and pure-core tests do not prove those gates.
