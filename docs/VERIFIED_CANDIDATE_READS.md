# 完整候选读取的短期复用

完整建筑可以由多个运输分片组成，但分片不是独立建造范围。客户端必须取得并核验完整原候选，随后再执行原服务端基线核验和独立世界确认。

## 为什么需要优化

原资源读取对 metadata 及每一个分片都重新进行终态语义检查、读取原 native bundle、把整栋建筑转换为世界差异并生成全部预览。它保持了原资产约束，却让连续分片下载重复执行整栋处理。优化仅减少重复的语义计算，不省略完整文件核验，也不调整模型预算、运输容量、工作线程期限或世界权限。

## 信任边界

只有资源所有者自己启动、正常退出并交回完整重建结果的原工作线程，才能建立一个私有内存复用记录。该记录绑定任务、参考输入、准备 hash 和候选 hash，保存已证明的候选及 patch-set 身份；它不是客户端字段、磁盘证书、任务恢复租约或建造许可。

记录最多一份、序列化最多两倍 metadata 额度，硬生命周期为五分钟。读取不会续期。任务身份不同或记录过期时，当前请求使用原完整重建路径；失败、取消、关闭及准备／绑定／原生证据上传会使记录失效。已取消或已关闭工作线程的迟到结果不能重新建立记录；多份回执拒绝。服务重启不从磁盘恢复复用记录。

## 每一次复用读取仍核验什么

- 重新枚举并逐字节读取、哈希全部原冻结输入、调用记录、参考像素、原 native 资产、当前采图与所有权证据。
- 重新读取、哈希完整候选的所有成员，包括没有请求的分片及其预览；核验完整成员集合和准确规范 metadata 字节。
- 保留物理目录、链接／硬链接、大小、打开前后文件身份检查及原总容量限制；最后再次核验原证据集合。
- 只保留被请求的一个原 patch／preview，不重新生成几何，不接受自行重算 hash 的磁盘替代候选。

工作线程、队列、输入、输出和执行期限不扩大；私有核验回执与公开结果合计占用同一个原工作线程输出额度，而非另加额度。HTTP 输入不接受 `cohort` 或 `verification`，内部复用回执不进入公开响应。完整集核验并不等于新鲜服务端世界核验，更不允许应用单片。

## 验证边界

纯生命周期与小型物理成员测试覆盖身份、硬期限、不可变副本、未请求成员篡改、缺失／额外成员、自重哈希替换、原证据编辑、硬链接、目录重定向及取消。Lite 合成共享管线另观察真实资源工作线程：首次完整重建、随后复用、篡改拒绝及失效后的重新完整重建，结果与原完整候选一致。模型回答均为合成数据，不是实际模型能力、建筑质量或 GPU 性能证据。

完整四档、HTTP、免费全量回归、准确新包与自身 CI 尚须通过后再发布源码里程碑；新包的游戏链、完整放置存盘、保护撤销、取消、真实模型与发行门槛需各自验收。仍在运行的旧验收及其冻结来源不受此开发分支修改。
