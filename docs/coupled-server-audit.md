# Original coupled candidate server audit

The independent coupled protocol has a separate server audit and fresh BEFORE
entry. They require the same server-owned Capture object, player, selection,
baseline and original dispatched coupled SEND. Matching downloaded hashes or a
copied Capture cannot adopt an old task, legacy audit or confirmation.

The bounded worker reconstructs the complete original native input and checks
all ordered parts and previews against that reconstruction. The server tick
accepts it only while the original ownership and baseline remain current. A
read-only report is not a world-write capability or proof of native physics.

Fresh BEFORE compares the full original edit region and captured six faces,
not just the proposed writes or one transport part. It uses bounded server
ticks and nonloading chunk lookups, retaining the actual original chunk
instances. The report is rechecked when read; changed world/selection/context,
unloaded or replaced chunks, explicit cancellation and shutdown invalidate it.
No replacement snapshot is captured automatically.

The independent coupled audit participates in the shared new-building,
single-patch, legacy-whole and read exclusion matrix. Its own retained audit
does not self-block the next original BEFORE. Task discard cancels both worker
and scan lifetimes and removes their usable server-owned results.

This is a read-only server integration, not final placement or a player
release. A separate native lease, final explicit consent, same-asset native
placement and protected undo, installed projection and physical-save evidence
remain required. Source-wiring checks and the pure exclusion matrix supplement
Java/native regressions; none alone establishes installed server behavior,
model reliability, image understanding or architectural quality.
