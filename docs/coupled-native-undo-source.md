# Native coupled inverse source

The inverse native source is distinct from the forward source. Only the same
live grouped apply's sealed complete prefix supplies its inverse origin. The
original server-compiled object, input, player, world and selection remain
identity-bound; an archive inspection or equal report cannot replace them.

A separate owner-bound, one-use UNDO ticket is consumed before native handoff.
It is not an APPLY ticket or model/SEND consent. The source also claims its
exact private inverse world and original inverse Plan once. Failed or unknown
outcomes do not permit a new source, new journal, retry or replay.

The inverse starts a new change-watch epoch at explicit confirmation, not at
late disk completion. It never refreshes the original AFTER target facts.
Unrelated changes during initial journal preparation invalidate that epoch.
Native reads stay inside original C and currently loaded chunk identities;
writes stay in original W minus P with exact ordered original inverse rows.

An original complete door is restored upper then lower without an intervening
tick/cancel boundary. If a later player edit affects either half, the inverse
core preserves both halves and their written support. A preserved whole group
advances the source's ordered cursor without arming or writing. An armed,
half-written, replayed or reordered group cannot be marked preserved.

The original AFTER lookup is built and frozen with the inverse plan off the
server tick. The tick maintains only its own restored overlay, avoiding a
full-target index build during native source startup. This does not adopt
later target changes into the original lookup.

The source uses native inverse state/support preflight and complete-group
postchecks. Failure after a possible partial mutation remains review-required,
not a complete-group receipt. Physical-save durability is never inferred.

The server undo gateway retains only the latest original live apply and its
sealed complete prefix. Preparation checks the original archive on a worker
without claiming the inverse. A distinct final UNDO confirmation transfers
the native source; the original inverse journal must return before any native
source or tick writer is constructed. Preparation cancels independently of
confirmed work. Active/queued disk and retiring CPU work remain mutually
exclusive with the other operation families even after a reply times out.

This source, server gateway and their pure-core tests do not implement the
player confirmation UI or installed-game acceptance. Those remain mandatory
separate gates before offering coupled modification as a player-facing release.
