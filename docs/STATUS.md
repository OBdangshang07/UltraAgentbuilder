## 本轮稳定性源码修复

Codex 适配器现在保留失败回合中可读的回答数据，并记录准确的容量错误分类。分类仅接受原回合的失败完成通知或有关闭时间的完整原始历史，且必须没有任何回答输出。部分输出、评论输出、超时、断线、相似错误文本和没有关闭时间的历史都不会被误认成空输出容量错误。不保存推理或未列入允许范围的供应方错误详情。这个分类是后续恢复策略的基础，本轮没有启用模型容量自动重试，旧请求和原失败任务的政策不变。

选区任务还修复了一个状态查询竞争：查询期间，刚观察到的本地写入控制器恰好结束时，可以在原有最多三次读取内重新核验同一日志。查询不会新增调用或预留，不接管原本就已停止的控制器，不接受缺失记录、哈希损坏或其他写入者，也不会把未知调用改报成功。

第一轮全量 Node 回归共 1398 项，1395 项通过、1 项失败、2 项跳过；该失败在定向测试中重现，暴露了上述状态查询竞争。修复并新增覆盖后，新的全量回归共 1400 项，1398 项通过、2 项跳过、0 项失败。376 份 JavaScript 语法检查零失败，发布与命名检查 10 项全部通过。修复后的 Java 回归共 501 项，500 项通过、1 项跳过、0 项失败，候选 JAR 构建成功，184 份内置文件的字节哈希与源码逐一一致。跳过项不计作通过，前一失败结果不改写。

以上验证均未调用真实模型、未写入玩家世界，没有新增游戏或建筑质量验收。候选 JAR 未作为正式发行版发布，也未覆盖正式安装。明确启用、同一总预算内的有限容量恢复，以及真实完整 CBD 和同资产游戏事务仍需后续完成。

### 容量恢复前的只读回执核验

新增核验器将准确的空输出容量分类与原任务日志、真实调用预留、派发计数、模型与推理强度、原 thread/turn、提示词、输出 schema、回答文件和私有回执逐一核对。原生复核图片与用户参考图片分别走各自的任务内允许路径，实际像素哈希同时绑定提供方请求和组件调用。改动没有改变旧日志或提供方请求的哈希版本。

检查不创建或修改文件、不读回提供方历史、不调用模型、不退还预算，也不授予重试或世界写入权限。未知结果、部分输出、评论输出、错误消息变体、换模型、篡改记录、错图、路径逃逸和文件链接均不能取得有效核验凭据。通过核验也不表示原建筑任务成功。

新增 19 项免费模拟测试覆盖完成通知、准确原历史、已关闭错误重放、未知原调用的只读回执恢复、原生图片及单图/双图/四图参考输入。扩大的定向回归 76 项全部通过；本阶段完整 Node 回归共 1419 项，1417 项通过、2 项跳过、0 项失败。379 份 JavaScript 语法检查零失败，发布与命名检查 10 项通过。Java 共 501 项，500 项通过、1 项跳过、0 项失败，候选构建成功。实际 JAR 的 186 份内置文件逐一核对字节哈希，183 份应内置源码齐全；跳过项不计作通过。

本阶段仍是显式有限容量恢复的核验底座，没有接通自动恢复、费用确认开关或新的真实完整建筑验收。最终预算保护、取消与重放、恢复关系审计、参考图发送确认和全流程验收尚待完成。旧失败任务、未知回合和冻结运行时保持不变。
