# Native world query admission

The coupled placement oracle accepts only seven exact world-read methods:
block state, fluid state, three height values and the two height-boundary
overloads. Their runtime Method identities are captured by typed Java calls,
so normal release remapping applies to those calls. Development method-name
strings are not a portable admission key for an installed intermediary JAR.

Unrecognized calls fail closed rather than forwarding to the live world.
The native reader still enforces original loaded chunks, context bounds,
world height, exact states and protected block entities. Pending door halves
remain a complete matched pair; native vanilla support checks still run before
and after the group. This fix does not expand world-write scope or bypass
the original final confirmation, BEFORE scan, journal or protected undo rules.

Named development tests alone cannot prove installed remapping or a saved
world. The final remapped JAR still needs an installed native-oracle check and
the same complete generation, world projection, placement and save gates.
