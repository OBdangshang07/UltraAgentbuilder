# UltraAgentbuilder 开发指南

公开分支是独立源码仓库，不依赖维护者的模型会话、Minecraft 世界或其他项目。以下命令仅用于源码构建和免费测试，不启动付费生成任务。

## 环境

完整候选 JAR 的打包当前要求 Windows x64、Node.js 22.19.0 和 Java 17 JDK。Node 安装目录必须包含上游 `LICENSE` 文件，打包会一并保留该许可。Gradle Wrapper 使用 8.12.1，Fabric Loom 首次构建需要联网下载依赖。

## 本地检查

在仓库根目录运行：

```powershell
npm ci --ignore-scripts
npm run check
npm test
npm run test:studio
```

`test:studio` 运行生成、Bridge 和设计的离线套件，使用模拟模型回答，不是免费调用真实模型。临时数据写入项目 `build` 目录；成功后清理本轮临时内容，失败日志保留。需要足够可用磁盘空间，建议至少预留 5 GiB。

## 构建模组

确认 `JAVA_HOME` 指向 Java 17 JDK，`node` 对应目标版本，然后运行：

```powershell
cd mod
.\gradlew.bat test build
```

输出位于 `mod/build/libs`。用户安装 remap 后的主 JAR，不安装 sources JAR，也不安装开发验收辅助 JAR。打包从源码生成内置 Bridge，并核对版本和协议，不读取本机账号或生成历史。

隔离游戏验收不在默认测试中自动运行。必须建立独立实例与新世界，明确实际安装的 JAR、成品资产、操作范围和玩家确认；不要用正式世界代替测试世界。

### Windows 长实例路径

Java 17 在 Windows 上可能无法启动超过系统原生路径长度的 Node 可执行文件，
即使文件存在。内置配套会在启动前检查完整路径：普通实例仍在原 `bundles`
目录解包；较长实例仅把 JAR 中哈希校验的配套解包到
`%LOCALAPPDATA%/UltraAgentbuilder/builtin-companion/bundles`，不下载程序。
任务、连接记录和日志仍在原实例的 `voxel-studio/data`，不会迁移账号或存档。

现有原运行时先核验，原件不覆盖；缓存按完整 manifest hash 分版本并加锁复用。
缓存路径不可用、被重定向、损坏或仍过长时明确失败，不改代理、驱动或系统设置，
也不通过重新发送模型任务处理启动失败。这项源码改动仍须精确安装包和游戏验收。

目录策略可能使 Java 把同一父目录内的移动报告为跨设备移动，继而拒绝移动
非空目录。此时不反复重试目录移动，也不关闭加密或其他系统保护：只在新建的
目标目录内按原清单逐文件校验复制，最后写入原清单作为就绪标记。已有目标不
覆盖，缺失或被修改的就绪标记、部分复制及损坏文件都不能启动服务；原解包
暂存目录保留。普通目录移动同样采用不覆盖语义，发布后再次校验实际字节。
这些安装兼容检查不改变模型预算、任务重试权限、实例数据或世界写入权限。

Bridge 的 CLI 入口对启动路径和模块路径分别解析物理文件身份，以兼容应用
容器中的不同逻辑路径表示。指定的数据目录也仅规范路径表示：核验逻辑和
物理路径的全部父目录及同一文件身份，拒绝符号链接、目录联接和身份变化，
不迁移数据或重新绑定任务。路径适配仍须完整回归、实际内置启动和安装验收。

## 本地 Bridge 调试

如需单独调试，可运行：

```powershell
npm run studio:bridge -- --data-dir .studio-data
```

服务只允许精确的本机回环连接。连接文件含令牌，不得提交、截图或分享。启动服务本身不会授权真实模型调用或世界写入。
