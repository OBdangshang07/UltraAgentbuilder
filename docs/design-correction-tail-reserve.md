# Funding an unapproved design correction

A new experimental staged Ultra Bridge request can explicitly select
`assemblyCompletionReserve: "design-correction-v1"`. It retains the existing
three alternatives, four prototype responsibilities, package ceiling, geometry
checks and confirmed total call limit. Saved requests without this field retain
their original scheduling; no journal is upgraded or failed call refunded.

Every prototype attempt then protects three tail calls, rather than two:
one design edit, one potential geometric correction and another concept review.
The later initial design edit is allowed only when it can fund that correction,
all current first-construction packages and final review. A correction spends
the reserved slot rather than keeping it reserved indefinitely. All cumulative
candidate/ownership checks and independent re-review remain mandatory.

For a 26-call, five-package synthetic task, seven distinct earlier rejections
can be followed by a rejected design edit, one correction, new concept review,
all five packages and final review. This is scheduling evidence, not a promise
that arbitrary model output will pass or that a building is aesthetically good.
An eighth earlier rejection may make the protected path unaffordable. The
runtime stops before consuming the reserved tail; it never skips work, accepts
an unapproved concept or silently raises the caller's limit.

The option is a separately versioned Bridge request contract, not yet an
automatic selection in the normal game UI. It supplies neither model-send nor
world-placement authority. Real-model, exact-candidate game/consent verification
is still required before ordinary player rollout.
