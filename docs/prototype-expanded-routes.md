# Prototype seed and full-building route validation

This opt-in source workflow fixes a mismatch between single-instance prototype
requirements and a route check performed before expansion. A legal task-owned
repeated opening can contract to one seed and restore every floor through an
explicit recipe. Checking the temporary seed as a finished building previously
rejected that case before its full expansion could be inspected.

New tasks may explicitly select `assemblyPrototypeValidation: expanded-routes-v1`
with staged Ultra, quality v4, native review and safe recovery. This freezes
prototype policy v6 in the original preflight/input/journal. Omitted selection
retains v5. Frozen older tasks are not upgraded, reinterpreted or resent. Call
ceilings, provider output-token inheritance, reserved tail, design allocation,
camera policy, ownership and placement confirmation remain unchanged.

With recipes, the intermediate seed still goes through the real compiler and
all cell/owner/package-region checks. Its package receipt explicitly says
`previouslyCheckedRoutesPreserved=false`. The full expansion then runs normal
package checks against the previous checked **full** expansion, including every
previously established entry, passage and stair route. A short or wrong recipe
cannot erase upper-floor access. With no recipes, ordinary full seed checks
remain required. Read-only terminal auditing reconstructs the same distinction
from the original policy, recipes and saved seed/full assets; it never compiles
a substitute or accepts a scope-only seed as completed geometry.

The model receives stage-specific instructions explaining this order and the
continuing full-floor obligations. No geometry is repaired, clipped, renamed
or granted broader rights automatically. This is not a route relaxation for
the final building, an aesthetic certificate or world-write permission.

Synthetic tests use authored full-block scenes and exact saved worker outputs,
not private model answers or native quality images. They reproduce the old
rejection, exercise new full-task/durable replay and reject missing/short
expansion, changed owners/regions and an unauthorized legacy inspection marker.
The normal client now exposes a default-off `通路校验` option for staged Ultra
v4. Explicit selection adds only `assemblyPrototypeValidation` to a NEW task;
leaving the required workflow clears it. Ordinary and reference builders use
the same selection, and both fee confirmation and exact current-request checks
retain it. The client requires the exact version-6 validation policy; omitted
selection retains version 5 and cannot silently gain the new policy. Reference
preparation v2 retains the selection, while legacy v1 rejects it.

Free source validation passed 31 related Node checks and 51 Java tests across
eight suites, including policies for all 22–26-call budgets, composed recovery/
camera/reserve options, altered/missing policy rejection and legacy consent.
The source-only candidate compiled and built, but this UI selection has not yet
completed a new installed-game gate. Real-model same-session acceptance,
complete same-asset placement and release gates remain separate work.
