# 显式有限容量恢复（实验功能）

新建 Codex 组件任务可显式提交 `assemblyProviderRecovery: "bounded"`。
默认省略此字段；历史请求、任务、确认和日志保持零提供方重试。
这不是默认重试策略，也不是玩家端无人值守验收已完成的声明。
玩家创作页已提供默认关闭的开关；开启选择本身不调用模型。
生成前必须重新确认完整费用合同，旧确认不能授权新选择。

## 玩家操作

选择组件化制作、已连接的 Codex、确切模型及该模型已声明的明确推理强度，
再选择“容量恢复：开启 · 原预算内”。跟随默认强度不能开启。
随后点击生成，在组件化预算确认中检查模型、推理强度、原总上限、
失败计费及恢复边界。参考图片的本地准备和独立 SEND 页展示相同合同。

更改模型、推理、提示词、档位、调用上限、质量、原型、恢复选项或世界，
原确认失效，须重新预检。切换 Agent 或离开组件流程会关闭该选择。
历史失败和未知任务不会因为开启新选项而被升级或重发。

## 预检和确认

仅新建 `generationMode: "scene"`、`sceneWorkflow: "components"`、
`agent: "codex"`、`assemblyRecovery: "safe"` 的任务可选。
必须显式提供模型 ID 和其支持的推理强度，不可使用 `default` 或等待
派发时再解析默认值。预检不调用模型、不预留调用，也不构成生成确认。
实际提交仍须 `assemblyConfirmed: true` 和准确、稳定的任务 key。

调用上限、制作包上限、输出 token 配置和全部必需职责不变。
预检返回固定的 `assembly.providerRecovery` 合同以及费用与失败边界说明。
客户端不得自定义等待时间、次数、换模、退款或放置权限。

## 恢复边界

仅原调用正常关闭、原回执独立核验且确认完全没有输出的 Codex 容量
失败可恢复。全任务最多 2 次新调用，依次等待 10／30 秒，可取消等待。
等待后和新的持久预留前均重新核验原回执、模型与强度、提示词、schema、
附件及总预算；必须仍能保护原完整制作尾程，否则停止。

开启不保证每个阶段都能恢复：原预算不足以保护完整尾程及纠错余量时，
仍安全停止，不追加额度。例如本地 Lite、8 次图像复核夹具在首轮容量
失败后剩余 7 次，保护路径需要 8 次，因此未派发恢复调用。

原失败与新调用都可能计费并占用已确认总额度。失败不退款，恢复不增加
额度、不换模型或强度、不缩小建筑或删掉必需制作包。普通错误、截断、
部分输出、评论输出和未知结果不获得此重试权限。已预留的未知恢复调用
也不重发，只能观察准确原调用的关闭回执。旧任务不会被自动迁移。

## 验证与限制

进度显示实际第几次等待及 10／30 秒策略，不伪装成剩余时间倒计时。
等待期间可取消；派发或只读观察原调用后不继续显示等待。
详情保留原失败和每次恢复预留，失败不改记成功。

免费测试使用真实 Bridge HTTP、持久调用日志、Codex 适配器的原证据存储
及只读独立审计路径，仅模型运输和答案由合成夹具替代。
两个全新隔离开发实例已通过默认关闭与明确开启的游戏测试：正常界面
选择、一次费用确认、一次提交、提交回执丢失后只查原 key、面板关闭后
自动纠错及最终投影。开启流程包括一次合成容量失败、真实策略等待，
共 7 次合成调用，失败保留；关闭流程共 6 次。两组均完成同一资产的
实际放置、保护式撤销、取消后撤销、正常退出及停止后存盘核验。
全部提供方运输均为免费模拟，没有真实模型调用，未打开正式世界。

这些结果不代表真实模型无人值守、建筑审美、v4 分阶段原型、多图融合、
Iris 或跨机器性能已经通过。游戏测试使用源码开发实例，不是正式安装验收。
未完成组件稿、未闭合回执和诊断资产仍不可发布或建造。
后续仍须完成新真实完整任务、真实成品同资产事务及发行验收。
